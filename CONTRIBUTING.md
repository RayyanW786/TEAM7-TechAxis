# Contributing Guide

## Project Status

This guide reflects the final Team 7 workflow used during development.

## Team 7 Members

Team members should:

1. work from their own branch using the format `{name}-develop`
2. make their changes on that branch
3. open a pull request targeting `develop`
4. wait for review before merging

## Non-Team Contributors

Non-team contributors should:

1. fork the repository
2. create a branch for their changes
3. open a pull request targeting `develop`
4. wait for review before merging

## General Expectations

- Keep commits focused and clearly named.
- Include any relevant setup, schema, or environment notes in the PR.
- Avoid mixing unrelated changes in the same pull request.
